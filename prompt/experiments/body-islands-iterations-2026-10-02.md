# 正文穿插广告：多方案迭代记录

日期：2026-10-02。范围：本机 Prompt 实验环境，生产提示词 SHA-256 保持
`66c1984919801b1022b467593dd636815732eb826df95bd204d19ea47a8e8438`。

## 结论

完整输出正文／广告分段，比直接输出广告首尾更有希望解决跨正文合并。
本轮较优候选为“原广告识别 + 完整分段复核 + 程序切除内部正文”，仍处于实验阶段。

在最后一组全新请求中，每视频各 5 次：

- MC 的 124.310 秒正文 5/5 次完整保留；推广引入语仍有遗漏。
- 航母的 30.148 秒正文 4/5 次完整保留；另一次误圈 12.952 秒，评分仍为 0.95。
- 完整分类前一组曾通过 5/5；重复试验显露了偶发误判。所有轮次、失败与费用一并保留。

本轮测试 14 版提示词、2 种修剪／复核流程、40 个不同视频，共 155 次真实 API 调用。
该样本规模用于定位问题与筛选方案，正式采用需要固定方案后的更大规模验证和人工边界复核。

网页入口：启动 `npm run prompt`，点击 **正文穿插 · 实验报告**。
报告是本次实验的固定快照；批次详情按当前有效名单重算。

## 实验约束与口径

- 使用 `deepseek-flash`，`thinking: disabled`、temperature 0。
- 保持生产定义部分；迭代局部连续性、示例、分段和复核协议。
- 五列协议输出上限 2048 tokens；分段／对象表等实验上限 8192，JSON 协议设置 `response_format`；局部逐句上限 4096。输出预算属于实验变量。
- 完整字幕使用相同编号和文本归一化逻辑。标题、字幕与候选内容保持外部数据身份。
- 普通运行每批并发 2；局部逐句复核按窗口顺序执行。
- 严格校验编号覆盖、顺序、区间、类型、评分；格式失败原样记录。
- 自动跳过仍按 ≥0.90 评分与原始累计区间达到 50% 的保护规则计算。
- 社区对照是参考一致性。正文检查区 `probe` 与正式人工标注分开，MC 检查区来源明确区分。
- 用户移除名单保持原样。执行时跳过已移除输入；未扩大到全量 570 例付费重跑。

## 保守的内部正文修剪

直接替换原结果会同时改变外边界、漏检和置信度，因此另试：

1. 保留原版输出的广告候选。
2. 用完整分类 v2 独立分析同一字幕。
3. 把同类型相邻分类块合并，只切掉候选内部两端都有广告的正文块。
4. 保留原候选外侧边界、原评分与原始 50% 保护判定。

它限定新增误圈的来源，仍可能因错误“正文”判断造成广告遗漏。
首次用已保存输出做零新增调用派生验证，两个样本各 5 个分类结果均能保留正文。
该阶段部分原候选复用旧轮次，按来源记录，完整流水线新请求复测另做一组。

最终两阶段新请求，每视频每轮 2 次，10 个结果 / 20 次调用：

| 两例 × 5 次，以社区对照计 | 原版    | 内部正文修剪 |
| ------------------------- | ------- | ------------ |
| IoU                       | 51.05%  | 87.30%       |
| 正文误跳率                | 17.521% | 0.672%       |
| 广告遗漏率                | 0.572%  | 7.316%       |

航母保留违例仍有 1 次，MC 推广引入边界漏标带来召回回退。自动对比判定 `blocked`。
组合运行 `7c1440c5-8e9f-4fba-a7b1-3be8737f5d27` 保存两阶段请求与原始输出。
组合记录的 API 用量是源请求的合计；核算支出时只统计源记录一次。

## 最后一种尝试：局部分句复核

只查看原候选，25 句一窗、两边各附 5 句上下文。逐句输出对象与正文／广告分类，程序再切出内部正文。

- 航母：2 个窗口，切出 152–163，同时把广告内类比的 146–147 错切为正文。
- MC：3 个窗口，只切出 9–49；仍覆盖 14.720 秒专项正文，广告引入语有遗漏。

每例先试 1 次，合计 5 次新增调用；原始候选复用最终基线。
运行 `44b37211-02f4-48d9-9dec-0ef080cab764`。
这个结果表明“颗粒度更细”也可能丢失前后推广关系，保持该方案初筛状态。
