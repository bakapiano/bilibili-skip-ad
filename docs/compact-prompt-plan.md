# 模型输入输出精简方案与决策

记录日期：2026-10-01。用户确认后已在 `0.1.6` 实施，提示词版本 `ad-cues-v3-pipe`。
兼容后端和官网 ZIP 已部署，Chrome 商店和 Greasy Fork 更新由后续发布完成。
验证记录见 [五列协议实测](testing/pipe-protocol-2026-10-01.md)。

## 已确认的输入方向

用户要求记下：模型的数据输入只保留视频标题和逐行「全局字幕编号|正文」。
System 消息继续提供识别规则、数据边界和输出格式要求。

```text
标题：视频标题

1|第一句字幕
2|第二句字幕
```

`bvid`、`cid`、分 P、`video_key`、完整字幕哈希及逐句时间戳由本地任务上下文管理。
标题保留用于理解视频主题；分段输入继续沿用全局字幕编号，窗口范围由本地保存。

## 已确认的五列输出

用户确认采用竖线分隔的五列纯文本，一行一段广告：

```text
82|105|转转|赞助口播与下单引导|0.95
```

- `start_id`、`end_id`：起止字幕编号，包含两端，负责映射时间。
- 品牌：用于界面展示。
- 简短说明：尽量控制在30字内，保存为内部 `reason`。
- 评分：0到1的模型自评分，衔接现有阈值。
- 零广告返回 `NONE`；多广告升序输出，互不重叠。
- 品牌与说明的反斜杠、竖线和换行通过 `\\`、`\|`、`\n`、`\r` 转义。
- 总结由本地按广告数量生成并标明程序汇总，证据列表为空，保持来源清晰。
- 视频身份和字幕哈希通过发起请求时的本地快照补齐，继续用于存储和共享缓存。

内部缓存和共享 API 继续使用结构化 JSON，模型通信格式由适配器转换。

## 实施约束与验证

1. 保留发起请求时的视频、字幕、窗口和任务身份快照；响应关联原任务，页面切换时丢弃失效的播放器更新。
2. 校验五列文本、转义、整数编号、当前窗口范围、起止顺序、区间重叠和评分范围，再映射原始时间戳。
3. 共用输入构造和输出适配，覆盖 Chrome、油猴、DeepSeek 与本地 Qwen POC。
4. 更新提示词/输出版本和缓存身份；评估共享协议兼容，保留旧数据。
5. 本地生成的说明或证据展示明确标明来源，避免将程序生成内容标作模型判断。
6. 模拟回归覆盖页面切换、乱序响应、越界编号、零广告、多广告、截断及恶意字幕；真实调用比较同一视频的 token、费用、延迟和边界。

上一轮已实现的输入精简与实测结果见 [验证记录](testing/compact-prompt-2026-10-01.md)。
