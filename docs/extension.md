## 安装与首次使用

1. 在 Chrome 打开 `chrome://extensions`，开启开发者模式。
2. 点击「加载已解压的扩展程序」，选择本仓库中的 `extension/` 目录。
3. 扩展设置页填写个人 DeepSeek Key，勾选「将当前视频标题和字幕发送至 DeepSeek」并保存。
4. 打开或刷新 B站标准视频页，点击 Chrome 工具栏的 BiliSkip 图标，再在弹窗中点击「分析当前视频」。
5. 展开广告标记，先「试听第 1 段边界」，核对后开启自动跳过。撤销会返回跳过前的时间，并保留该段继续播放。

首次加载由用户在 Chrome 中完成；当前自动化工具对扩展管理页有明确访问限制。此交接完成后继续真实浏览器 E2E。安装状态与验收清单见 [验收状态与历史排查](testing/e2e-status.md)。

更新本地源码后，在扩展管理页重新加载该扩展，再刷新 B站页面。Key 和 IndexedDB 数据使用当前扩展 ID 对应的浏览器存储；移动扩展目录或卸载扩展会影响数据保留，请先导出需要的标记。

## 默认行为

- 自动分析和自动跳过初始关闭。线上查询和自动上传默认开启，弹窗保留手动上传入口。
- 新模型结果校验并写入本地后，读取最新设置并自动上传一次。缓存读取复用已有结果；失败或受限流时保留本地标记和错误回执，提供手动重试提示。
- 设置中 `autoUpload` 单独控制自动上传，`sharedUpload` 是全部上传的总开关。旧版本已有的上传关闭设置保持原值，已明确关闭的自动上传设置持续保留。
- 弹窗每 500ms 读取当前视频页的内存状态，字幕和网络查询由显式刷新或页面切换触发。弹窗命令核对扩展来源、当前视频身份、记录版本和区间编号。
- 页面打开时读取字幕并查本地缓存；点击分析后才调用模型。用户可在设置页主动开启前台视频自动分析。
- 本地缓存键包含 BV、分 P、CID、字幕 SHA-256、模型与提示词版本。重新打开/刷新视频时核对最新元数据和字幕。
- 模型返回 `start_id` / `end_id`，客户端映射字幕时间，验证区间顺序、证据、边界与视频指纹。
- 自动跳过阈值默认 0.90，且累计广告长度须少于全片一半；常规播放中自动跳过，拖动尚未完成和媒体切换时等待就绪。暂停时主动定位按下述规则处理。
- B站原生主进度条和底部细进度条以金色色带标出广告区间，色带允许鼠标事件传递给原进度条。
- 自动跳过开启时，用户主动定位到符合阈值的广告区间会跳到广告末尾，即使该段此前已经跳过。暂停状态下的主动定位也会响应；播放与暂停行为沿用 B站原生控件。
- 试听和撤销暂时保留对应片段；后续主动定位会重新应用自动跳过规则。拖动中的 seek 完成后再判断目标区间。
- 「重新分析（再次计费）」明确发起新的分析。并发点击同一视频会复用在途任务；不同视频的模型请求串行处理。
- 模型请求等待上限 25 秒，采用一次请求策略。超时或输出校验失败时保留原有有效标记，并记录已获得的用量。
- Service Worker 重启后会把未完成任务标为中断，提供手动重试提示。
- 页面内推荐视频/分 P 切换会清除旧标记，以 Chrome 当前标签页 URL 核对新视频。弹窗的近期模型请求/缓存命中统计仅统计当前视频。

## 字幕链路

先通过 `/x/web-interface/view` 获取并核对 BV / CID / 分 P / 时长，读取 `/x/player/wbi/v2` 的字幕轨道，必要时使用 `/x/v2/subtitle/web/view` Protobuf 接口，最终下载 B站字幕 CDN JSON。

已适配 `subtitle.bilibili.com` 编码字幕地址。轨道选择顺序为中文 → 英文 → 其他语言，各组内人工字幕优先于 AI 字幕；面板显示实际使用的字幕语言及来源代码。

播放器接口与 Protobuf 接口的轨道合并去重。Protobuf 接口返回空列表时，间隔 350ms 再读一次；备用接口失败时保留播放器接口已取得的轨道。下载或字幕校验失败会按优先级尝试下一条，每次加载最多请求 5 个不同的字幕资源，继续使用原有 HTTPS 域名、大小和时间轴校验。

不同字幕内容生成独立指纹，沿用原有本地和共享缓存键。V1 使用 B站现成字幕；自动语音转写可作为后续单独模块。B站接口属于网站实现细节，后续变化需要更新适配器。全部轨道为空时提示检查播放器字幕与登录状态。

## 本地数据与隐私

- `chrome.storage.local`：个人 DeepSeek Key、独立共享令牌、设置；限制为扩展可信上下文访问。普通 B站页面接收 Key 是否已配置的布尔值。
- `IndexedDB / biliskip-v1`：规范化字幕上下文、标记、任务、候选上传队列、最近 200 条事件。
- 扩展设置页提供缓存列表、标记导出和清除。统计中的缓存命中/模型请求数来自最近 200 条事件。
- 模型请求的标题和字幕仅发往固定官方地址 `https://api.deepseek.com/chat/completions`；Key 位于 Authorization 请求头。
- B站 API 请求沿用浏览器允许附带的站点会话；代码通过 fetch 发起请求，字幕 CDN 和模型请求使用 `credentials: omit`。
- 共享服务只接收约定的标识、指纹、标记和有限证据句；字段白名单见 [共享缓存协议](shared-cache-api.md)。
- 本机扩展存储按个人电脑账号保护。建议使用专用额度 Key；聊天中曾贴出的凭据可在提供方控制台轮换。

## 开发和验证

扩展运行代码为原生 JavaScript，测试使用 Node.js 22.13+ 的 22.x 或 Node.js 24+ 与 `fake-indexeddb`。开发依赖留在项目根目录，发布包只包含 `extension/`。协作与格式规范见 [AGENTS.md](../AGENTS.md)。

```powershell
npm ci --ignore-scripts
npm run lint
npm run lint:fix
npm run format
npm run format:check
npm run verify

# 校验、测试并生成 dist 下的时间戳 zip
npm run pack
```

`verify` 包含 ESLint、Prettier、Manifest 资源、JS 语法、本地 import、CSP、凭据字面量检查及正式回归测试。单元测试覆盖字幕解析、严格校验、请求边界、消息来源、缓存、并发、错误保留、共享协议和模拟 DOM 播放状态。

一次性真实接口联调和人工浏览器验证脚本归入 Git 忽略的 `.tmp/`。本机保留原脚本时，可运行 `node .tmp/smoke-live.js` 读取真实字幕，显式添加 `--deepseek` 发起付费分析。长期回归用例放入 `tests/`，常规检查使用模拟服务。
