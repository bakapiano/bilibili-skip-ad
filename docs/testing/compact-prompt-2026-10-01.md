### 费用与缓存条件

2026-10-01 重新读取官方 [模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)：
`deepseek-flash` 对应 DeepSeek-V4.1-Flash。空闲时段每百万 tokens：输入缓存命中 0.02 元、
输入未命中 1 元、输出 4 元；高峰时段分别为 0.04、2、8 元。

以下是 API 用量乘官方空闲时段单价的估算，账单仍以服务商实际扣费为准。高峰时段金额为下表两倍。

| 比较口径                       |      旧输入 |    精简输入 | 说明                                   |
| ------------------------------ | ----------: | ----------: | -------------------------------------- |
| 第一轮实际缓存命中量           | ¥0.00133868 | ¥0.00392300 | 旧请求已命中大量缓存，新请求首次冷缓存 |
| 第二轮实际缓存命中量           | ¥0.00144268 | ¥0.00131276 | 两边均有大量缓存命中，本轮约省 9.0%    |

结论：输入 token 的降幅是稳定的格式收益；实际账单还受输入缓存命中率与输出长度影响。

### 当前输出与下一步空间

本轮保持现有 JSON 输出协议：`video_key`、`transcript_sha256`、`summary`、`segments`，
每段包含 `start_id`、`end_id`、`brand`、`confidence`、`reason` 和 `evidence_ids`。
精简输入的两次调用分别输出 252、258 tokens。第二轮输出费用约占总费用 78.6%。

后续可先限制总结与理由长度、精简重复证据，再评估由本地当前任务上下文补齐身份字段的紧凑输出。
该方向需同步调整输出适配、任务绑定和版本校验，并通过新的真实对照；本轮保持现有输出字段。

## 本地 Qwen POC

独立 POC 位于 `dist/asr-poc/`。它复用正式版精简输入模块，使用 Qwen3-4B Q4F16、4096 上下文、
512 输出预算和 128 安全余量。默认目标 7 分钟、重叠 30 秒，逐段通过已加载模型的实际 tokenizer 检查完整请求预算。

每段保留全局编号；输出截断会缩小检测窗口重试。候选广告在扩展上下文中复核，冲突或过长区间单独标为待复核。
报告记录逐次原始输出、实际用量、规划用量差异与最终区间。所有数据保存在本机，正式扩展继续直连 DeepSeek。

跨段测试将广告横跨两个检测窗口的结果合并，并执行独立边界复核；最终输出一段广告。

分段累计 token 含重叠和复核的重复输入，和正式版 DeepSeek 单次整片输入分别计量。
小窗口控制峰值显存，同时增加模型调用次数；本轮机器还运行着其他 GPU 工作负载，耗时作为该环境观察值。
