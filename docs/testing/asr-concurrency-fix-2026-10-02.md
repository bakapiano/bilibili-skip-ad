# ASR与字幕分析任务锁拆分

日期：2026-10-02。基于扩展0.1.8、油猴0.1.8.3试用源码的本地修复。

## 原因与改动

`AnalysisService.analyze()`原先在整条流程外持有全局`busy`，从字幕读取、ASR到模型请求和上传都占用该锁。
油猴另外使用全局`analysis` Web Lock。因此，一个视频正在ASR时，其他有字幕视频也收到`BUSY`。

修复为以下范围：

- 同一视频／分P：扩展复用在途Promise；油猴跨标签页按视频／分P持有任务锁，保留重复计费保护。
- ASR：音轨获取和转写独占`asr`资源；调用识别器之前取得锁，资源忙碌时提供重试提示。
- DeepSeek：实际模型请求独占`model`资源；取得锁后才记录API调用并发出请求。
- 字幕、转写缓存和广告缓存读取独立进行。ASR期间，其他有字幕／转写缓存的视频可以完成广告分析。
- 油猴上传和设置锁保持原有范围。锁在成功或异常结束时释放。

同类资源采用原有忙碌提示策略。ASR与DeepSeek各允许一个在途请求，两类资源可以同时工作。
Worker初始化、完成后释放、模型下载缓存、提示词、输出协议、共享缓存身份均保持原样。

## 回归验证

先新增复现用例：修改前，普通字幕、转写缓存、已有广告缓存三种场景均被全局锁拦截；修改后全部通过。
新增6项固定模拟测试，并保留同视频去重、授权、模型失败用量和播放器生命周期回归。

覆盖范围：

1. 一个视频ASR未完成时，另一个视频凭字幕完成模型识别。
2. 同期第三个视频复用转写缓存；需要新ASR的任务保持资源互斥。
3. 模型请求进行时，其他视频仍可读取已有广告标记。
4. ASR失败后释放资源与视频任务锁，随后可重试。
5. 油猴跨标签页英文字幕分析通过，第二个ASR任务在音轨获取前被拦截。
6. 不同视频的模型资源竞争在发送和计费事件记录前检查，锁释放后正常执行。

`npm run verify`通过：ESLint、Prettier、扩展结构与凭据扫描、290项测试。
