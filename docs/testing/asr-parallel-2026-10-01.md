# SenseVoice CPU 多 Worker 对照

日期：2026-10-01。任务：在现有 CPU POC 上测试多线程/多核收益。
本轮新增独立 POC，生产扩展和线上缓存保持原状。

## 结论

使用相同 SenseVoiceSmall INT8 模型和 sherpa-onnx WASM 运行时，将不同语音段分配给 1 / 2 / 4 个独立 Worker。
完整518.455秒音轨，本轮单路107.74秒、两路64.88秒、四路39.45秒，四路相对单路约2.73倍速度、减少约63.4%等待时间。
所有配置保留相同89个语音段、229条字幕，文字、tokens和token时间戳逐项一致。

## 架构与范围

当前使用的 WASM SIMD 发布构建在单个识别器内单线程运行，`numThreads=1`。
实测各实例的 WASM 内存为普通 ArrayBuffer；构建脚本包含的模型加载代码使用线程环境字段检查，运行时主体没有创建 pthread Worker 的路径。
这次实施的是 **多个 CPU Worker 并行识别不同语音段**，每个 Worker 有独立识别器、模型实例和 WASM 堆。

处理流程：

```text
模型文件读取/校验一次 → 分别初始化 N 个识别器
视频音轨 → Worker 0 实际运行 Silero VAD → 原始语音段波形
         → 分发到空闲 Worker → 保留文字/token时间戳
         → 按原段编号恢复顺序 → 同一个切句 v2 → 广告分析可用的字幕
```

所有配置均先计算VAD，再执行ASR任务队列。VAD参数、原始音轨、模型字节、token时间戳与切句算法保持一致。
测试输入来自 `BV1pFUDBKE8X`，使用此前保存的16kHz单声道WAV，无新音轨下载或付费模型调用。
动态队列每次把下一段实际VAD波形转交空闲Worker，结果按编号排序，避免完成顺序影响字幕。

## 本轮计时

机器：Ryzen 5 3600 / 6核12线程、32GB RAM、Chrome 154。
各轮包含真正运行的VAD与ASR，模型加载和音频读取单独记录。

### 65秒音轨，8段语音，32条最终字幕

| Worker数 | VAD阶段 | ASR阶段实际等待 | 转写合计 | WASM堆合计 |
| -------- | ------: | --------------: | -------: | ---------: |
| 1        |  0.68秒 |         13.12秒 |  13.81秒 |     512MiB |
| 2        |  0.75秒 |          8.98秒 |   9.73秒 |    1024MiB |
| 4        |  0.65秒 |          5.10秒 |   5.75秒 |    2048MiB |

### 全片518.455秒，89段语音，229条最终字幕

| Worker数 | VAD阶段 | ASR阶段实际等待 | 转写合计 | 相对单路 |
| -------- | ------: | --------------: | -------: | -------: |
| 1        |  3.71秒 |        104.02秒 | 107.74秒 |   1.00倍 |
| 2        |  4.53秒 |         60.34秒 |  64.88秒 |   1.66倍 |
| 4        |  4.33秒 |         35.11秒 |  39.45秒 |   2.73倍 |

全片Worker池初始化为2.55/5.36/9.45秒，含资源复制和识别器创建，采用错峰加载降低临时峰值。
从开始加载到转写、切句和结果指纹生成的本轮总耗时分别为111.18/70.45/51.67秒。
四路运行时各Worker解码时间之和约135.76秒，实际ASR等待35.11秒：这些任务在时间上重叠，体现多核并行。

以上每个并行数各跑一次短片段和全片。四路全片额外复跑为 **39.64秒**，复用已加载的Worker池，文字、tokens和时间戳与第一次完全一致。
系统同时有其他应用运行，CPU调度、内存压力与文件缓存会影响具体数值。

## 一致性与并行证据

- 单路、多路的音轨SHA-256完全相同。
- 每个音轨的VAD段数、原始起点样本索引、每段样本数量一致。
- 每段文字、tokens、token时间戳、语言及输出编号逐项一致。
- 三组短片段结果SHA-256：`9033cf53ee0e45445d84d4b340e26a6efe2c42b2768a0aea88149d3308278fc4`。
- 三组全片结果SHA-256：`edfc680ad9bc5bcfef9a6418d1a115a7c60fa3928219b6dda12274fd94d288af`。
- 单路新全片与9月30日原始报告的文字、tokens和token时间戳一致；边界仅存在最大约5.7e-14秒的浮点加法舍入差。
- Worker记录 `performance.timeOrigin + performance.now()` 起止时刻，离线检查峰值重叠任务数恰好为1/2/4。
- 所有最终字幕通过现有 `normalize()` 检查。

本次只验证语音转写及分段一致性，广告分析模型调用为0。

## 内存代价

每个 Worker 的 WASM 已分配线性内存为512MiB，四路合计2GiB。
模型虚拟文件系统、主页面保留的约252MB原始模型/运行时数据、音频缓冲与JavaScript对象还会额外占用内存。
模型文件在本机只需下载/缓存一份；运行中的识别器和工作内存按Worker数量增加。
额外的内存开销需要在正式集成时设置并行数上限、低内存回退、空闲释放与用户开关。

本轮系统整体CPU和空闲物理内存每秒记录到 `dist/asr-parallel/system-*.jsonl`。
这是整机观察，包含其他应用，作为环境信息而非插件独占内存计量。

## 已修正的实验问题

65秒首轮测试的进度提示中，毫秒值曾被直接标成“秒”。真实报告使用正确的秒换算，修正了该UI格式后再运行全片。
各成功/失败记录、阶段耗时和配置均按原始数据保存。
