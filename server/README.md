# 最小共享缓存后端

一个 Node 进程、一个 SQLite 文件，运行时使用 Node 自带的 HTTP 和 SQLite 模块。
后端负责共享标记的保存与读取，模型调用仍由插件使用用户自己的 DeepSeek Key 完成。

## 启动

运行环境：Node.js 22.13+ 的 22.x 或 Node.js 24+。当前已在 Node 22.23.2 验证，
该环境的 `node:sqlite` 会输出实验性 API 提示。

在项目根目录执行：

```sh
npm run server
```

默认监听 `127.0.0.1:8787`，数据库自动创建为 `data/shared-cache.sqlite`。
运行服务直接使用项目代码和 Node 标准库，开发依赖用于测试和静态检查。

需要自定义配置时，将 `.env.example` 复制为同目录 `.env`，修改后运行：

```sh
node --env-file=server/.env server/index.js
```

| 配置                       | 默认值                          | 含义                                                            |
| -------------------------- | ------------------------------- | --------------------------------------------------------------- |
| `BILISKIP_HOST`            | `127.0.0.1`                     | 监听地址                                                        |
| `BILISKIP_PORT`            | `8787`                          | 监听端口                                                        |
| `BILISKIP_DB_PATH`         | 项目 `data/shared-cache.sqlite` | SQLite 文件路径                                                 |
| `BILISKIP_SHARED_TOKEN`    | 空                              | 可选独立共享令牌；填写后查询和提交都须带该令牌                  |
| `BILISKIP_TRUSTED_PROXIES` | 空                              | 可信代理的实际连接 IP，逗号分隔；只有这些连接可提供 `X-Real-IP` |

## 限流与记录

- 每个来源 IP 的提交请求，相邻放行时间至少间隔 **1000ms**。
- 超限返回 `429`，响应头 `Retry-After` 提供建议等待秒数。
- 重复上传、无效 JSON、无效字段和认证失败都会消耗提交间隔。
- SQLite 事务串行决定是否放行，并发请求和服务重启沿用同一计数状态。
- 每日记录 `attempts`（收到的提交数）、`limited`（限流次数）、`stored`（新增标记数）。
- 每日次数用于观察，准入规则固定为每秒一次。
- IP 计数逻辑保留最近 **7 个 UTC 日期**，运行期间定期清理。
- IPv4 与 IPv4-mapped IPv6 地址统一；普通 IPv6 按 `/64` 网段共享限额。
- 同一出口 IP 的用户共享额度；查询与健康检查使用独立只读路径。

这套限流面向提交控量。一个来源持续按每秒一次提交，仍可积累大量记录；多 IP 也有各自的额度。
需要收紧内测参与范围时，可以配置独立共享令牌。部署时应同时关注磁盘空间和服务器负载。

## 缓存规则

采用当前约定的简化发布流程：**结构校验通过的首条有效提交直接成为共享缓存**。
同一视频、字幕指纹、模型和提示词版本，后续相同请求返回原回执，差异请求返回 `409`。
所有提交在幂等处理之前经过同一 IP 限流。

服务验证字段白名单、请求体哈希、视频绑定、ID、区间、评分范围和证据结构。
完整字幕留在插件链路，服务端依据上传数据进行结构校验。模型准确性、赞助事实和字幕指纹的真实性，
需要人工反馈或未来独立复核；当前 `published` 表示进入共享缓存。

插件取回结果后，还会针对本次完整字幕重新校验编号、证据和时间边界。
出现误标时可在服务器本机撤销该记录，后续查询返回 `404`；撤销记录保留占位，后续同键提交返回 `410`。

## 接口

| 请求                                             | 返回                                                               |
| ------------------------------------------------ | ------------------------------------------------------------------ |
| `GET /healthz`                                   | `200`，健康状态                                                    |
| `GET /v1/segments?...`                           | 命中 `200`；未命中或已撤销 `404`                                   |
| `POST /v1/candidates`                            | 新记录 `201`；幂等重试 `200`；限流 `429`；冲突 `409`；已撤销 `410` |
| `OPTIONS /v1/segments`、`OPTIONS /v1/candidates` | `204`，跨域预检                                                    |

请求及响应字段与 [共享协议](../SHARED_CACHE_API.md) 一致。
单次提交上限为 **64 KiB**，正文读取等待上限 **10 秒**。
查询和提交支持可选 `Authorization: Bearer <独立共享令牌>`。

## 公开域名接入

1. 在同一台服务器运行 Node 服务，保持监听 `127.0.0.1`。
2. 用现有 Nginx 的 HTTPS 域名转发到 `127.0.0.1:8787`，参考 `nginx.conf.example`。
3. 设置 `BILISKIP_TRUSTED_PROXIES=127.0.0.1,::1`。Nginx 必须用 `$remote_addr` **覆盖** `X-Real-IP`。
4. 插件设置中填写公开 HTTPS 域名根地址，分别开启共享读取或上传并授权域名；配置令牌时两端使用同值。
5. 新分析结果按设置自动上传；也可在工具栏弹窗点击「上传到线上缓存」，再点击「读取线上缓存」验证；其他浏览器可复用该标记。

当前线上目标、自动部署脚本和操作记录见 [DEPLOYMENT.md](DEPLOYMENT.md)。

转发链为一层自有 Nginx → Node；增加其他代理时，应重新核对实际连接地址和真实 IP 来源。
本机开发的 HTTP 地址用于服务测试，插件配置使用公开 HTTPS 域名。
正式运行可交给现有 systemd 或进程管理工具，固定工作目录和环境文件，使用单独的系统账号。

## 查看计数与撤销

使用相同配置和数据库文件执行：

```sh
npm run server -- stats
npm run server -- recent
npm run server -- revoke <submission-id>
```

通过环境文件启动服务时，管理命令也读取相同文件：

```sh
node --env-file=server/.env server/index.js stats
node --env-file=server/.env server/index.js recent
node --env-file=server/.env server/index.js revoke <submission-id>
```

管理命令在服务器本机运行。`recent` 显示最近 20 条标记；`stats` 显示最多 100 行 IP 日计数。
撤销保留数据库原记录供核对，已经进入其他用户浏览器本地缓存的副本需要由对应用户清理。

## 数据与隐私

服务器保存上传标记及有限证据，另保存来源 IP（IPv6 为网段）、UTC 日期和提交计数。
查询响应只投影标记字段。IP 日计数仅通过本机管理命令查看。
提交字段白名单确保 DeepSeek Key、B站 Cookie 和完整字幕字段留在各自链路；共享认证令牌来自请求头。
运行时为本进程创建的文件设置私有权限掩码，部署者仍需核对系统账号、数据目录权限和备份策略。
维护者应在实际共享服务的隐私政策中披露 IP 计数及保留期，数据库备份和代理日志单独管理。

## 验证

```sh
node --test tests/server.test.js
npm run verify
```

正式测试包含真实本机 HTTP + SQLite + 插件 SharedClient/IndexedDB 链路，
以及 1000ms 间隔、并发、重启、跨午夜、错误请求、代理伪造、幂等、冲突、撤销和数据保留。
